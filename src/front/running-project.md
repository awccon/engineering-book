# The Running Project

One application grows throughout the book, so every technology is learned in the context
of a real, evolving system rather than isolated toy examples.

> **Working name:** *Beacon* — a team knowledge base and support desk.
> (The name and domain are open for change in the master plan.)

| Book | What Beacon gains |
|---|---|
| I — C# | Core domain model, business rules and tests as a library + console app |
| II — Git | A repository, branching workflow and pull requests |
| III — Backend | An ASP.NET Core API with auth, validation, caching and background jobs |
| IV — SQL | A PostgreSQL schema, EF Core, migrations and tuned queries |
| V–VI — TS/React | A React + TypeScript frontend |
| VII — Full stack | Typed API contracts and end-to-end tests |
| VIII — Docker/Linux | Containers, Compose, and deployment to a Linux server behind Nginx |
| IX — Azure/DevOps | Azure hosting, CI/CD, monitoring and Infrastructure as Code |
| X–XI — Python/AI | Semantic search, RAG over the knowledge base, an AI support assistant |
| XII — Rust | A small high-performance companion service |
| XIII — Architecture | Design reviews: should Beacon be split? What would it take to scale? |
| XIV — Capstone | Production-readiness review of the complete system |
